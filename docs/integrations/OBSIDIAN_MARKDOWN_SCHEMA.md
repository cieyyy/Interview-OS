# Obsidian Markdown Schema

## Frontmatter

Every managed note contains:

```yaml
---
interview_os_id: "stable-entity-id"
interview_os_type: "project"
schema_version: 1
title: "Note title"
status: "active"
created_at: "2026-07-21T10:00:00.000Z"
updated_at: "2026-07-21T10:30:00.000Z"
last_synced_at: "2026-07-21T10:31:00.000Z"
source: "interview-os"
sync_enabled: true
tags: []
related_jobs: []
related_projects: []
related_knowledge: []
related_interviews: []
---
```

Strings are emitted as JSON-quoted YAML scalars. Arrays use YAML block sequences. File names and paths are not identity keys.

## Content Ownership

```markdown
# Title

<!-- interview-os:managed:start -->
Structured content generated by Interview OS.
<!-- interview-os:managed:end -->

<!-- interview-os:user:start -->
User-owned notes.
<!-- interview-os:user:end -->
```

Phase 1 preserves the user block. If the complete file hash differs from the last exported hash, Interview OS records a conflict and does not overwrite the file.

## Type Mapping

| Interview OS object | `interview_os_type` | Default folder key |

| ProjectExperience | `project` | `projects` |
| KnowledgeItem incident | `incident` | `incidents` |
| KnowledgeItem technical/project | `technical-knowledge` | `technicalKnowledge` |
| KnowledgeItem question | `interview-question` | `interviewQuestions` |
| KnowledgeItem answer / TrainingSession | `interview-answer` | `expressionTraining` |
| KnowledgeItem JD / JobDescription | `jd-analysis` | `jdAnalysis` |
| KnowledgeItem learning plan | `learning-plan` | `learningPlans` |
| KnowledgeItem company research | `company-research` | `companyResearch` |
| KnowledgeItem retrospective | `retrospective` | `retrospectives` |
| ResumeVariant | `resume-metadata` | `resumes` |

Resume export contains metadata and evidence links only. Full resume body export is not implemented in Phase 1.
