# MVP 范围、路线图与验收标准

## 1. 版本策略

## V0.1：产品原型与数据闭环

目标：验证“材料 → JD → 问题 → 回答 → 反馈 → 知识沉淀”。

包含：

- 本地工作区；
- 职业档案和项目经历；
- Markdown 知识库；
- JD 粘贴和结构化；
- 文字模拟面试；
- 一个 OpenAI 兼容模型接口；
- 训练记录与回写；
- 手动备份恢复。

不包含：语音、云同步、招聘网站抓取、公共题库市场、复杂多智能体。

## V0.2：可测试的 Windows MVP

增加：

- Windows 安装包；
- 自动保存和崩溃恢复；
- 全文搜索和筛选；
- 训练报告和进步趋势；
- 数据脱敏日志；
- Playwright 关键流程测试；
- 更新检查，但不默认静默安装。

## V0.3：AI 能力增强

增加：

- 远程 Dify 连接器；
- 本地 RAG 索引；
- 多模型 Provider；
- 语音输入与转写；
- 回答节奏、口头语和停顿分析；
- 简历与 JD 的证据化匹配。

## V1.0：可公开发布版本

增加：

- 稳定升级与迁移；
- 加密备份；
- 插件/连接器 SDK；
- 完整隐私说明和数据导出；
- 可选云同步；
- 多职业模板。

## 2. P0 验收场景

### AC-01 首次工作区

**给定**用户第一次启动应用，  
**当**用户选择 F 盘目录并完成最低档案信息，  
**那么**应用应创建工作区并进入工作台；重启后数据仍存在，且不强制注册。

### AC-02 项目经历

**给定**用户创建一个项目，  
**当**填写背景、职责、问题和结果并保存，  
**那么**项目应能被搜索、编辑、导出，并关联至少一条知识卡片。

### AC-03 JD 分析

**给定**用户粘贴一份有效 JD，  
**当**执行分析，  
**那么**系统应输出职责、必须技能、加分技能和匹配证据；AI 失败时原始 JD 不丢失。

### AC-04 单题训练

**给定**用户选择一份 JD 和一个项目，  
**当**开始训练，  
**那么**系统先展示问题而非答案，并在用户提交后返回分项反馈。

### AC-05 引导重答

**给定**首次回答缺少个人职责或结果，  
**当**系统完成评分，  
**那么**应先提出针对性澄清问题，再允许用户重答并对比两次回答。

### AC-06 真实性保护

**给定**上下文没有某项量化成果，  
**当**AI 优化回答，  
**那么**不得自动添加虚构数字；建议补充的内容必须明确标为待确认。

### AC-07 回写知识库

**给定**用户确认一版最终回答，  
**当**点击保存到知识库，  
**那么**系统应创建面试回答卡片，并保留与问题、项目和 JD 的关联。

### AC-08 断网能力

**给定**设备断网，  
**当**用户浏览、编辑、搜索和导出已有内容，  
**那么**这些操作应正常完成；仅 AI 功能显示离线提示。

### AC-09 凭据保护

**给定**用户保存 API Key，  
**当**检查普通配置、日志、导出和备份文件，  
**那么**任何位置都不得出现完整明文 Key。

### AC-10 备份恢复

**给定**一个包含档案、项目、JD 和训练记录的工作区，  
**当**执行备份并恢复到新目录，  
**那么**内容数量、关系和附件引用应保持一致。

## 3. 非功能目标

### 性能

- 10,000 条纯文本知识记录下，普通搜索的目标响应时间小于 500ms；
- 冷启动目标小于 5 秒，具体以目标测试机基线调整；
- AI 流式响应不得阻塞主界面编辑与保存。

### 可靠性

- 编辑内容自动保存；
- 数据写入采用事务或原子替换；
- 数据库迁移前自动创建恢复点；
- 单个附件损坏不得阻止整个工作区启动。

### 安全

- 外部输入按不可信内容处理；
- Markdown/HTML 渲染默认禁用危险脚本；
- URL、文件路径和连接器响应需要校验；
- 更新包必须校验签名或可信摘要；
- 日志和遥测默认最小化、可关闭。

### 可维护性

- UI、业务、存储、AI 和连接器分层；
- 核心业务不直接依赖具体模型或 Dify；
- 每个数据结构有 schemaVersion；
- 关键决策形成 ADR；
- P0 流程具备自动化测试。

## 4. 产品阶段决策门

进入系统设计前，需确认：

1. 产品名称与视觉气质；
2. MVP 是否仅做文字训练；
3. 是否将 Obsidian 文件夹作为主存储，还是以数据库为主、Markdown 为导出层；
4. 首个模型接口采用用户自带 Key 还是远程服务；
5. 后期需要对接的“另一个软件”的类型和读写范围；
6. 是否以个人作品优先，还是从第一版考虑商业账号体系。

在这些决策未确认前，可以制作低保真原型，但不应锁定最终技术架构。
