# Interview OS v0.6.0 基线审计

> 审计日期：2026-07-22  
> 审计基线：`1a1029d` / Interview OS `0.5.0`  
> 证据范围：`package.json`、`src/`、`tests/`、路由、领域模型、IPC、存储与构建配置。本文不以旧产品文档代替代码事实。

## 1. 技术与构建基线

- 桌面运行时：Electron 37。
- 渲染层：Vue 3、Vue Router 4、TypeScript 5、Vite 7。
- 图标：Lucide Vue；没有引入第二套图标库。
- 数据：本地 JSON 工作区，由 `AtomicWorkspaceRepository` 串行写入 `state.tmp`，轮换 `state.json` 与 `state.previous.json`。
- AI：OpenAI-compatible 与 Dify Provider，密钥由主进程安全存储隔离。
- 发布：electron-builder，已配置 NSIS 安装版与 portable 便携版。
- 自动化：15 个测试文件、55 个单元与集成测试；另有桌面主流程、字体一致性和打包应用 E2E。

## 4. 当前数据模型

`WorkspaceState.schemaVersion` 当前为 `2`，核心集合包括：

- 档案资产：`profile`、`projects`、`knowledge`、`jobs`。
- 求职执行：`syncedJobs`、`applications`、`resumeVariants`、`companyWatches`。
- 岗位采集：`jobSources`、`jobSyncRuns`、`jobFilterPresets`、`jobAlertRules`。
- Agent：`careerSearchPlans`、`careerAgentRuns`、`careerMemory`。
- 训练：`trainingSessions`，内部保存问题、回答尝试、诊断和总结。
- 集成：Obsidian 设置、同步索引、冲突和运行记录。

当前迁移器只接受 schema 1/2 并统一写为 2。旧状态缺少的新数组会补空值，旧岗位会重新计算智能字段。

## 5. 已存在的问题

### 5.1 产品结构

- 侧栏有 17 个同级入口，信息架构过平，用户难以围绕“发现岗位→Offer”形成主线。
- `AI 助手`是 15 行的训练跳转页，与`面试训练`形成重复入口，但并不存在两套聊天数据。
- `职业档案`同时承载项目资产，项目没有独立一级工作空间。
- 岗位同步、岗位洞察和 JD 中心相邻但上下文切换依赖用户手动完成。
- 训练报告与训练入口分离，历史会话缺少统一教练上下文。

### 5.2 知识体系

- 已有 Markdown、标签、关联 ID 和复习时间，但编辑器仍是纯 textarea。
- `[[WikiLink]]`仅用于 Obsidian 导出，应用内部没有解析、跳转和自动关联。
- 没有反向链接计算、知识关系图和统一属性编辑器。
- 训练结果能生成知识卡片，但 JD、项目、技能和训练之间的关系展示不足。
- 知识没有 `private / publish-ready / public` 可见性状态。

### 5.3 数据与迁移

- `TrainingSession`只允许单个 `projectId`，不能表达统一教练会话的多项目上下文。
- 没有统一 `CoachSession`、消息序列和多模式会话类型。
- 迁移发生在读取阶段，但没有“升级前专用备份 + 迁移报告”机制。
- Obsidian 设置属于现有用户数据，v0.6.0 不能删除；应降级为设置中的可选兼容导出能力。

### 5.4 UI 与工程结构

- 全部样式集中在超过 1300 行的 `global.css`，组件和页面职责边界弱。
- 仅有 4 个共享 Vue 组件，大量按钮、卡片、输入框和空状态直接在页面重复编写。
- 当前字号为 28/22/17/15/13/12/11px，与 v0.6.0 指定的 24/18/16/14/12px 不一致。
- 间距大量直接写数值，尚未形成完整 4px 语义 Token。
- 页面最小宽度固定 1000px，桌面端可接受，但窄窗口缺少收缩导航策略。
- 颜色已有变量，但页面仍包含大量直接颜色值，语义状态色不完整。

## 6. 重复功能与融合策略

| 当前入口 | 重复点 | v0.6.0 处理 |
|---|---|---|
| AI 助手 + 面试训练 | AI 教练入口重复 | 合并为“AI 职业教练”，旧路由保留为兼容别名 |
| 面试训练 + 训练报告 | 会话执行与历史割裂 | 同一教练工作区内提供训练、复盘与历史页签 |
| 职业档案中的项目 + 训练项目选择 | 项目上下文分散 | 增加“项目资产库”入口，继续复用原项目数据 |
| JD 中心 + 岗位工作台详情 | 岗位发现与分析跳转成本高 | 岗位中心保留职位池，并提供显式“进入 JD 分析”动作 |
| Obsidian 双链导出 + 内部知识关联 | 能力方向重叠 | 以内置知识空间为主，Obsidian 保留为可选兼容导出 |

## 7. v0.6.0 修改范围

1. 升级版本号与 `WorkspaceState` schema 3。
2. 新增统一 `CoachSession`，无损迁移现有 `trainingSessions`，并保留旧字段兼容。
3. 导航收敛为工作台、AI 职业教练、简历工坊、岗位中心、JD 分析、知识空间、项目资产库、求职管道、公司关注、能力成长、数据中心和设置。
4. 建立 `src/design-system` Token 与 `components/ui` 基础组件，页面逐步迁移。
5. 将工作台改为今日任务、训练、待优化回答、待学习技能和目标岗位。
6. 升级知识空间：Markdown 预览、属性、标签、内部双链、反链和图谱。
7. 增加迁移前自动备份、迁移结果记录和 schema 1/2/3 测试。
8. 更新产品、架构、UI、迁移、测试和发布文档，并构建 Windows 安装版与便携版。

## 8. 明确不做

- 不删除 v0.5.0 页面能力、IPC、集合或用户记录。
- 不在 v0.6.0 强制启用招聘网站爬虫、自动沟通或自动投递。
- 不上传招聘平台 Cookie、密码或登录态。
- 不删除 Obsidian 数据和设置；仅把它从知识主流程降为兼容集成。
