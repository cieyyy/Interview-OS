# v0.5.0 到 v0.6.0 数据迁移报告

## 范围

工作区 schema 2 升级到 schema 3。保留职业档案、项目、知识、JD、职位池、简历、投递、公司关注、训练、报告、设置和 Obsidian 兼容配置。

## 新增字段

- `WorkspaceState.coachSessions`
- `WorkspaceState.migrationHistory`
- `KnowledgeItem.jobIds/projectIds/skillNames/visibility`

## 转换规则

1. 旧知识缺失的新数组补 `[]`，可见性补 `private`。
2. 每个旧 `TrainingSession` 生成一个 `CoachSession`；问题为 coach 消息，回答为 user 消息。
3. 原 `trainingSessions` 不删除。
4. 原 schema 1 数据继续经过既有 v1→v2 规范化，再统一到 schema 3。

## 备份与恢复

- 迁移前副本：`backups/workspace-before-v2-to-v3-*.json`。
- 迁移报告：`migrations/migration-v2-to-v3-*.json`。
- 原子落盘：`state.tmp` 写入成功后替换 `state.json`。
- 当前状态损坏时读取 `state.previous.json`。

## 验证结果

自动化测试验证：项目、知识、旧训练、旧回答、CoachSession 和迁移记录均存在；备份及报告文件成功创建。测试只使用临时目录，未操作真实用户数据。

## 回滚

关闭应用后，将迁移前备份复制回 `database/state.json`，并使用 v0.5.0 程序启动。由于 v0.6.0 不删除旧字段，回滚不需要数据库 DDL；v0.6.0 新增的 schema 3 字段不会被旧版主动消费。
