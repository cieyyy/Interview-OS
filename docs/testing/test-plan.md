# 测试计划

## 1. 目标

验证产品核心闭环、数据可靠性、安全边界和 Windows 桌面可用性。

## 2. 测试层级

### 单元测试

- JD 关键词与能力分类；
- 训练问题生成；
- 回答分项评分；
- 输入校验和日志脱敏；
- 引用清理和实体更新。

### 集成测试

- 原子仓库首次创建、保存、重载；
- 临时文件/损坏状态恢复；
- Markdown 导出；
- 备份清单与摘要；
- Provider 假实现的超时和错误映射。

### Electron E2E

1. 启动应用并显示工作台；
2. 创建项目经历；
3. 创建知识卡片；
4. 导入并分析 JD；
5. 开始训练、提交回答并看到分项反馈；
6. 保存最终回答并在知识库中看到结果；
7. 重启应用后数据仍存在。

## 3. 异常与安全测试

- AI 断网、超时、401、429、5xx；
- 超长文本、空输入和危险 HTML；
- 非法文件名和路径穿越；
- API Key 不出现在日志、状态和导出；
- Renderer 无法直接使用 Node.js；
- 外部链接不在应用内部任意导航；
- 备份失败不破坏当前工作区。

## 4. 发布测试门槛

- `npm run typecheck` 通过；
- `npm run test` 通过；
- `npm run test:e2e` 通过；
- `npm run build` 通过；
- Windows 打包产物生成并能启动；
- 无 P0/P1 未解决缺陷；
- 已知限制写入测试报告。
