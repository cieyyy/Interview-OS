## 4. 已验证的用户闭环

1. 应用首次启动并显示空工作台；
2. 加载演示职业档案和项目数据；
3. 新建知识卡片并立即显示；
4. 导入目标 JD 并完成离线结构化分析；
5. 选择 JD 和项目开始面试训练；
6. 提交回答并生成分项评分；
7. 保存最终回答到知识库；
8. 关闭并重启应用；
9. 验证知识、JD 和训练数据仍然存在；
10. 启动打包后的 `win-unpacked` 正式程序并完成隔离数据写入。
11. 在职业档案、知识库和 JD 中心分别选择本地文件并验证识别预填；
12. 验证导入结果在用户保存前不会写入业务数据；
13. 验证 Chat Completions 图片载荷和 Responses API 自动回退。

## 5. 修复记录

- 修复 Vue 响应式 Proxy 直接传入 Electron IPC 时出现 `An object could not be cloned`；
- 将 IPC 输入统一转换为纯 JSON 数据；
- 将 preload 改为独立运行，避免沙箱预加载脚本依赖应用模块；
- 增加 Renderer 退出和加载失败诊断；
- 修复 Electron E2E 关闭后再次读取进程对象导致的测试清理异常；
- 修复安装版与便携版产物同名覆盖问题。

## 7. 已知限制

- 当前发布文件未使用商业代码签名证书，Windows 可能显示未知发布者提示；
- AI Provider 已实现配置、密钥隔离和连接测试接口，但未使用真实付费 Key 做在线内容生成验收；
- 当前无云同步、自动更新、招聘网站自动抓取和团队协作；
- 扫描版 PDF 需要先转换为图片；图片识别依赖用户配置的视觉 AI Provider；
- 当前使用 Electron 默认图标，正式公开发布前应补充品牌图标；
- Electron 测试在 Codex 受限进程沙箱内无法创建 Renderer，需在已授权的项目测试进程中执行；正式打包程序本身已验证可运行。

## 8. 风险判断

- 未发现 P0 / P1 功能缺陷；
- 本地数据原子保存、上一版本恢复、备份和 Markdown 导出已具备；
- 默认不启用联网 Provider，离线功能不依赖外部服务；
- 项目总占用约 1.80 GB，其中包含开发依赖、Electron 打包缓存、新旧版本发布产物和解析依赖；运行时不会持续无上限增长。
