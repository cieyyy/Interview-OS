# 简历识别设计

## 1. 目标

简历导入采用“本地优先、证据优先”的混合方案。目标不是把任意版式百分之百还原成原文，而是尽可能稳定地提取基础档案和项目经历，同时不编造简历中不存在的信息。

## 2. 识别流水线

```text
用户主动选择文件
  ↓
文件文字提取
  ├─ TXT / Markdown / JSON / CSV / LOG：本机直接读取
  ├─ DOCX：本机解析 OOXML
  ├─ DOC：按文件签名识别 OLE Word / RTF / MHTML / DOCX 伪扩展名
  ├─ 文本型 PDF：本机提取文本层
  └─ 图片 / 扫描型 PDF：仅在 Provider 已启用时进行 AI OCR
  ↓
版式归一化
  ├─ 合并被空格拆开的中文字段名，例如“工 作 年 限”
  ├─ 兼容冒号、制表符和表格空格分隔
  └─ 保留段落和列表边界
  ↓
结构识别
  ├─ 基础信息：姓名、岗位、年限、学历、求职方向、技能
  └─ 项目分段：项目标题、日期范围、描述、职责、成果、技术环境
  ↓
版式纠错
  ├─ 双栏 PDF 的项目名称与详情重新按出现次序配对
  ├─ “项目经验Eclipse”等粘连标题拆分
  └─ 项目名丢失但内容存在时保留为“待命名项目”
  ↓
保存与人工复核
```

## 3. 为什么有时只能得到“待命名项目”

部分旧版 Word 简历使用文本框、浮动对象或图片保存项目名称。文字提取器可能只读到项目描述和职责，读不到视觉上显示的标题。系统会保留可验证的项目内容，并标记为“待命名”，而不是根据描述猜测一个名称。用户可在职业档案的“项目经历”中编辑后保存。

## 4. 隐私边界

- DOC、DOCX、文本型 PDF 和文本文件默认只在本机读取，不发送给 AI；
- 图片和没有文本层的扫描 PDF 需要视觉识别，只有用户主动导入且已启用 Provider 时才会发送；
- 识别结果写入本地工作区，不写入日志；
- 批量回归审计只统计格式、识别数量和错误，不复制或提交真实简历内容；
- 自动化测试使用匿名化文本，不包含样本中的姓名、电话、邮箱或公司隐私。

## 5. 当前支持与限制

已适配中文与英文项目标题、常见日期范围、表格字段、双栏 PDF、旧版 DOC、RTF/MHTML 伪装的 DOC、项目名称与详情错序等情况。图片质量过低、加密 PDF、手写内容、纯艺术字、复杂浮动文本框仍可能需要人工核对。
