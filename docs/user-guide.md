# Interview OS v0.5.0 使用指南

## 1. 当前版本说明

仓库源码版本为 `0.5.0`。v0.5.0 Windows 安装版和便携版尚未重新生成，因此开发与验收建议从源码启动：

```powershell
cd D:\资料\release\IOS
npm install
npm run dev
```

软件不依赖 Docker、WSL、Hyper-V、Redis 或 PostgreSQL。已有 v0.4.0 发布文件可以继续用于旧版验证，但不会包含本指南中的新模块。

## 2. 首次使用顺序

1. 在“职业档案”填写目标岗位、经验、学历、技能和项目经历。
2. 在“知识库”保存技术知识、故障案例、问题、回答和复盘材料。
3. 在“求职 Agent”输入城市、岗位、薪资、排除项和偏好，生成搜索计划。
4. 在“岗位同步”导入或同步岗位，使用筛选、对比和审计确定优先级。
5. 将岗位转换为 JD，创建定向简历和求职机会。
6. 在“求职管道”和“求职日程”跟踪投递、沟通、面试和下一步动作。
7. 针对目标 JD 进行中文或英文面试训练。
8. 在“能力图谱”和“训练报告”查看证据缺口与补强路线。
9. 可选：在“设置”连接 Obsidian Vault，导出长期职业知识资产。

## 3. 岗位同步

### 3.1 浏览器扩展

1. 启动 Interview OS，进入“岗位同步 > 数据源”。
2. Chrome 打开 `chrome://extensions/`，启用开发者模式。
3. 选择“加载已解压的扩展程序”，加载仓库中的 `browser-extension/`。
4. 在扩展弹窗中填写软件显示的同步令牌。
5. 打开支持的招聘网站搜索页，点击“同步当前页面”。

当前扩展面向 BOSS 直聘、猎聘、智联招聘、前程无忧和拉勾的可见页面。招聘网站结构变化后可能需要更新选择器。

扩展只读取用户当前打开页面中的可见职位，不读取密码、不导出 Cookie、不绕过登录或验证码，也不会自动发送沟通消息或投递简历。

### 3.2 岗位筛选与审计

- 可按关键词、排除词、城市、行业、来源、最低薪资、匹配度、可信度、远程和新鲜度保存筛选规则。
- 岗位详情展示七维匹配、推荐理由、数据质量、风险和偏见提示。
- 最多可选择四个岗位进行横向对比。
- 岗位可进入 JD 中心、简历工坊、求职管道和面试训练。

## 4. 求职 Agent

在目标输入框中使用自然语言描述求职需求，例如：

```text
帮我找杭州云原生、AI 平台或技术支持岗位，20K 以上，不要外包，双休优先。
```

系统会解析城市、关键词、薪资、排除项和偏好，生成本地计划并查询当前职位池。Agent 不会在没有连接器的情况下假装已经搜索互联网；职位池为空时会明确提示需要先同步岗位。

求职记忆用于保存偏好、真实经历、岗位反馈、决策和备注。不要在记忆中保存密码、Cookie 或 API Key。

## 5. 简历与投递

- “简历工坊”可按目标 JD 创建多个版本，选择项目证据、技能和核心亮点。
- 自动草稿只使用职业档案中的真实内容；缺失信息需要本人补充。
- “求职管道”记录公司、岗位、来源、地点、薪资、状态、优先级、截止时间、下一步动作和备注。
- 沟通话术是草稿，发送前必须人工检查。
- 当前投递模式为人工或辅助状态记录，不会自动操作招聘网站。

## 6. 面试训练

- 支持中文和全英文训练。
- 支持标准模式和 2/4/6/8 轮动态压力面试。
- 可使用文字或麦克风作答，并朗读题目。
- 每轮可查看证据缺口、逻辑问题、面试官质疑点、STAR 参考和简历建议。
- 英文模式的问题、推荐回答、教练建议和后续追问全部使用英文。
- 未配置 Provider 时使用本地规则；Provider 失败不会阻止本地保存。

系统不会编造经历或数字。无法从职业档案和项目中确认的事实会保留“【需要本人补充】”。

## 7. 文档导入

JD 中心、职业档案和知识库支持 PNG、JPG、JPEG、WEBP、PDF、DOC、DOCX、TXT、Markdown、JSON、CSV 和 LOG，单文件最大 12 MB。

- 文本和文本型文档在本机解析。
- 图片和扫描 PDF 只有在用户主动选择且启用视觉 Provider 时才会发送到外部服务。
- 识别结果需要人工核对，特别是姓名、年限、岗位、公司、项目名称和量化数据。

## 8. Obsidian 集成

### 8.1 连接与导出

1. 进入“设置 > 知识库与 Obsidian”。
2. 选择现有 Vault，或创建 Interview OS 专用 Vault。
3. 配置工作子目录、附件目录、同步间隔和导出范围。
4. 点击“首次同步预览”，检查将创建或更新的文件。
5. 点击“立即同步”执行单向导出。

知识编辑器支持“保存并同步”：本地保存先完成，随后尝试导出。

### 8.2 安全与当前边界

- Interview OS 本地工作区仍是权威数据源。
- 不读取或修改 `.obsidian`。
- Markdown 使用稳定 `interview_os_id`、YAML frontmatter、WikiLinks 和受管内容块。
- 外部修改会触发冲突保护，不会被静默覆盖。
- 当前不支持从 Vault 导入、重命名识别、文件监听或双向同步。
- “在 Obsidian 中打开”需要本机安装 Obsidian 并注册 `obsidian://` 协议。

## 9. AI Provider

设置页支持 OpenAI-compatible 和远程 Dify。API Key 通过 Electron 安全存储处理，不进入普通工作区、Markdown 导出或日志。

只有主动使用图片识别、AI 陪练或其他明确标注的 AI 命令时，相关选定内容才会发送给 Provider。连接测试会发起一次最小生成请求，而不是只检查 `/models`。

## 10. 数据、备份与恢复

默认数据目录由 Electron 用户数据目录决定。可在启动前指定独立目录：

```powershell
$env:INTERVIEW_OS_DATA_DIR = 'D:\Interview-OS-Data'
npm run dev
```

- 工作区采用临时文件和原子替换，并保留上一版本。
- 设置页可创建带 SHA-256 清单的本地备份和 Markdown 导出。
- Provider 密钥不包含在普通备份中。
- Obsidian Vault 不是工作区备份的替代品。

## 11. 开发与测试

```powershell
npm run typecheck
npm run test
npm run build
npm run test:e2e
npm run package:win
```

Electron E2E 会启动隔离的桌面测试实例。v0.5.0 当前自动化基线为 55 个单元与集成测试，以及主流程和全模块字体一致性 E2E。
